# Демо-профиль

Из этой папки при `SEED_DEMO_DATA=true` берутся названия муниципалитетов для пустой базы.
Учреждения с корпусами, пользователи и заявки генерируются кодом в `backend/app/seed.py`.

- `demo.json` — условный профиль, лежит в репозитории.
- `local.json` — свой профиль с настоящими названиями.
  В git не попадает. Если файл есть, используется он.

Формат у обоих файлов один: `{"municipalities": [...]}`. Первый муниципалитет в списке —
пилотный: в нём половина учреждений, учреждение демо-директора и заявки. Явно выбрать
файл можно переменной `SEED_FILE` в `.env`.

Ключ `"okrug": "<название округа>"` — система работает в одном округе: все демо-учреждения
создаются в нём, а в уже созданной демо-базе учреждения, бригады и пользователи других
округов удаляются при следующем запуске (рабочую базу без демо-пользователей это
не трогает).

Профиль читается один раз, на пустой базе. Чтобы применить изменения, базу нужно
пересоздать: `docker compose down -v && docker compose up -d`.

`program.local.json` — расчёт управления по программе оптимизации (тоже не в git, в нём ФИО
из приказов). Раздел `fill` описывает, как заполнить школы под этот расчёт, включая
`extra_schools` (школы вне расчёта, штатка по нормативу) и `brigades` (бригады управления
и их сотрудники). Заполнение пересоздаётся, когда меняется его версия в
`backend/app/services/program.py`.
