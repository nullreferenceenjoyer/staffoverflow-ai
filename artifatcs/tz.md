Понял. Тогда это надо делать **не как кадровый архив и не как полный документооборот**, а как узкий модуль:

> **Нормативная численность для АУП и вспомогательного персонала**  
> с анализом: где не хватает ставок, где сверх норматива, где нет данных.

Без персональных данных. Без ФИО. Без окладов. Без договоров. Без «кто именно лишний».  
Система должна показывать только агрегированную картину:

> «В школе № 5 по АУП сверх норматива 0,75 ставки, в основном за счёт группы „секретари / делопроизводство“».

Или:

> «В детском саду № 12 по вспомогательному персоналу не хватает 1,5 ставки уборщиков служебных помещений».

---

# 1. Главная идея

Добавить раздел:

```text
Штат и нормативы
```

или, лучше по смыслу:

```text
Нормативная численность
```

Внутри — не много вкладок, а максимум две:

```text
1. Анализ численности
2. Нормативы
```

Где:

- **Анализ численности** — основной рабочий экран: где дефицит, где излишек, где нет данных.
- **Нормативы** — справочник коэффициентов и документов-оснований.

Штатка нужна не как список людей, а как набор утверждённых и/или занятых ставок по группам должностей.

---

# 2. Что важно сразу зафиксировать

## Без персонализации система может показать только агрегат

Если не хранить сотрудников, нельзя честно показать:

> «Иванов лишний».

Но можно показать:

> «По группе „уборщики служебных помещений“ норматив — 8 ставок, занято — 9,5 ставки, излишек — 1,5 ставки».

Это уже решает задачу понимания, где перебор.

Поэтому в модели нужны только:

```text
группа должностей / позиция без ФИО
количество утверждённых ставок
количество занятых ставок, если есть агрегированные данные
период
учреждение
корпус, опционально
нормативный коэффициент
документ-основание
результат анализа
```

# 3. Кого считаем

Только две большие категории:

```text
АУП
Вспомогательный персонал
```

Учителей, воспитателей, педагогов дополнительного образования и прочих преподавателей в этом модуле не анализируем.

## 3.1. АУП

Примерные группы:

```text
Руководство
Специалисты АУП
Делопроизводство и обеспечение
```

Примеры позиций внутри групп:

```text
Директор
Заместитель директора
Главный бухгалтер
Начальник хозяйственной части
Секретарь
Делопроизводитель
Архивист
Диспетчер
```

Но в интерфейсе лучше показывать не хаос должностей, а **группы нормирования**:

```text
Заместители директора
Бухгалтерия и финансово-экономическая служба
Делопроизводство
Хозяйственная часть
Прочее АУП
```

## 3.2. Вспомогательный персонал

Можно разделить на два подблока, но не перегружать:

```text
Учебно-вспомогательный персонал
Обслуживающий персонал
```

Примеры:

Учебно-вспомогательный:

```text
Педагог-психолог
Учитель-логопед
Социальный педагог
Библиотекарь
Методист
Инструктор по труду
```

Обслуживающий:

```text
Уборщик служебных помещений
Дворник
Повар
Помощник воспитателя
Охранник
Электрик
Слесарь-сантехник
Гардеробщик
```

Для анализа удобно использовать не каждую должность отдельно, а **группы нормирования**, например:

```text
Уборка помещений
Охрана
Пищеблок
Техническое обслуживание
Учебно-вспомогательные специалисты
```

## 4.6. Нормативные коэффициенты

Это главная таблица для анализа.

Таблица:

```text
normative_coefficients
```

Поля:

| Поле | Зачем |
|---|---|
| `id` | Идентификатор |
| `document_id` | На основании какого документа |
| `personnel_group_id` | К какой группе применяется |
| `top_category` | Можно задать категорию целиком: АУП / вспомогательный |
| `institution_type` | Школа, детский сад, гимназия и т. п. |
| `scope_level` | Регион, муниципалитет, учреждение |
| `scope_id` | Конкретный муниципалитет или учреждение, если локальный норматив |
| `metric` | На что считать: учащиеся, классы, группы, площадь |
| `unit_size` | На сколько единиц метрики, например 100 учащихся |
| `fte_per_unit` | Сколько ставок на этот блок, например 1 ставка |
| `min_fte` | Минимум ставок |
| `max_fte` | Максимум ставок |
| `rounding_step` | Округление: 0,25 / 0,5 / 1 |
| `rounding_mode` | В большую сторону, в меньшую, математически |
| `tolerance_abs` | Допуск в ставках, например 0,25 |
| `tolerance_pct` | Допуск в процентах, например 5% |
| `priority` | Приоритет при конфликте норм |
| `effective_from` | Действует с |
| `effective_to` | Действует до |
| `is_mandatory` | Обязательный норматив или рекомендация |
| `comment` | Пояснение |

Пример условного норматива:

```text
Группа: Делопроизводство
Метрика: учащиеся
Единица: 300 учащихся
Ставок на единицу: 1
Округление: 0,25
Допуск: 0,25 ставки
Документ: приказ № ...
```

То есть:

```text
На каждые 300 учащихся — 1 ставка делопроизводства.
```

Другой пример:

```text
Группа: Уборка помещений
Метрика: площадь
Единица: 1000 м²
Ставок на единицу: 1
Округление: 0,25
```

То есть:

```text
На каждые 1000 м² — 1 ставка уборщика.
```

Важно: конкретные коэффициенты должны настраивать аналитик/управление, а не быть зашитыми в код как истина.

# 5. Как считать излишки и дефицит

## 5.1. Базовая формула

Для каждой группы персонала:

```text
норматив = сумма по применимым коэффициентам
```

Для одного коэффициента:

```text
ставка_часть = значение_метрики / unit_size * fte_per_unit
```

Пример:

```text
Учащихся: 840
Норматив: 1 ставка на 300 учащихся
unit_size = 300
fte_per_unit = 1

840 / 300 * 1 = 2,8 ставки
```

Потом округляем:

```text
rounding_step = 0,25
rounding_mode = up

2,8 -> 3,0 ставки
```

Затем применяем минимум/максимум:

```text
min_fte = 1
max_fte = 4

итого норматив = 3,0
```

---

## 5.2. С чем сравниваем

Нужны два режима.

### Режим 1: по штатке

```text
fact = approved_fte
```

Показывает:

> В штатном расписании предусмотрено больше/меньше ставок, чем норматив.

### Режим 2: по занятости

```text
fact = occupied_fte
```

Показывает:

> Фактически занято больше/меньше ставок, чем норматив.

Для задачи «понять, где лишний сотрудник» важнее режим по занятости.

Но если занятость не ведётся, система должна уметь считать хотя бы по штатке.

---

## 5.3. Отклонение

```text
deviation = fact - required
```

Если:

```text
deviation > 0
```

значит излишек / сверх норматива.

Если:

```text
deviation < 0
```

значит дефицит / не хватает.

---

## 5.4. Допуск, чтобы не пугать мелочами

Нельзя каждый раз писать «излишек 0,01 ставки».

Нужен допуск.

Например:

```text
tolerance_abs = 0,25
tolerance_pct = 5%
```

Статус:

```text
если abs(deviation) <= max(tolerance_abs, required * tolerance_pct)
    status = normal
```

Пример:

```text
Норматив: 4,0
Факт: 4,2
Отклонение: +0,2
Допуск: 0,25

Статус: норма
```

А если:

```text
Норматив: 4,0
Факт: 5,0
Отклонение: +1,0

Статус: излишек
```

---

## 5.5. Статусы

Я бы использовал 5 статусов:

```text
deficit      — не хватает
surplus      — сверх норматива
normal       — в пределах нормы
no_data      — нет данных для расчёта
warning      — данные неполные или норматив спорный
```

В интерфейсе лучше человеческими словами:

```text
Дефицит
Сверх норматива
Норма
Нет данных
Требует проверки
```

Не надо писать «лишний сотрудник».

Правильнее:

```text
Излишек 1,0 ставки
Сверх норматива на 1,5 ставки
```

---

## 5.6. Severity

Чтобы сортировать проблемы:

```text
low
medium
high
```

Пример правила:

```text
high, если отклонение >= 1,0 ставки или >= 20%
medium, если отклонение >= 0,5 ставки или >= 10%
low в остальных случаях
```

Но пороги должны быть настройками.

# 6. Что делать, если данных нет

Это очень важно, иначе анализ будет врать.

## 6.1. Нет штатки

```text
status = no_data
missing_reason = нет утверждённой штатки
```

Нельзя показывать дефицит или излишек.

## 6.2. Нет метрик

Например, не указана площадь.

```text
status = no_data
missing_reason = не указана площадь помещения
```

## 6.3. Нет норматива для группы

```text
status = warning
missing_reason = норматив не настроен
```

## 6.4. Нет occupied_fte, но выбран режим «по занятости»

```text
status = no_data
missing_reason = нет данных о занятой численности
```

Или автоматически переключаться на «по штатке», но обязательно показывать подпись:

```text
Расчёт по утверждённой штатке, фактическая занятость не известна
```

# 7. Интерфейс: как сделать просто и не нагромоздить

## 7.1. Одно входное место

В меню добавить:

```text
Нормативная численность
```

Не надо делать отдельный гигантский раздел «Штатка», отдельный «Нормативка», отдельный «Документы», отдельный «Аналитика».

Лучше:

```text
Нормативная численность
├── Анализ
└── Нормативы
```

Максимум ещё скрытая служебная вкладка для администратора:

```text
Импорт / справочники
```

Но её не надо показывать всем.

---

## 7.2. Главный экран: Анализ

Сверху простые фильтры:

```text
Период: 2026/2027
Категория: [АУП] [Вспомогательный]
Основа: [Занятость] [Штатка]
Территория: весь регион / муниципалитет / учреждение
Статус: все / только проблемы
```

Не больше.

### Сводные карточки

Четыре карточки:

```text
Дефицит: 12
Сверх норматива: 7
Норма: 14
Нет данных: 3
```

Клик по карточке фильтрует таблицу.

### Таблица

Максимум колонок:

```text
Учреждение | Норматив | Факт | Отклонение | Статус | Что не так
```

Пример:

```text
Гимназия № 5        5,25    6,00    +0,75    Сверх норматива    Делопроизводство
Школа № 12          4,00    3,25    -0,75    Дефицит            Заместители
Детский сад № 3     8,00    8,25    +0,25    Норма              
Школа № 44          —       —       —        Нет данных         Не указана площадь
```

Если выбрано «Вспомогательный»:

```text
Учреждение | Норматив | Факт | Отклонение | Статус | Что не так
Детский сад № 3    10,00   8,50   -1,50   Дефицит   Уборка помещений
Школа № 5          12,00  13,25   +1,25   Сверх     Пищеблок
```

Главное: не показывать сразу все должности. Сначала уровень учреждения. Детали — по клику.

---

```text

```

### Блок «Итог»


### Блок «По группам»

```text
Группа                 Норматив   Занято   Отклонение
Заместители директора     3,00     3,50      +0,50
Делопроизводство          1,00     2,00      +1,00
Бухгалтерия               1,25     0,50      -0,75
```

### Блок «Почему так получилось»

Например:

```text
Применены нормативы:
— Заместители: 1 ставка на 12 классов, 34 класса
— Делопроизводство: 1 ставка на 300 учащихся, 840 учащихся
— Бухгалтерия: 1,25 ставки при числе учащихся свыше 800

Основание:
приказ управления образования № 123 от 01.09.2026
```

### Кнопки

Только нужные:

```text
Создать заявку
Исправить данные
Пересчитать
```

Не надо десять кнопок.

---

## 7.4. Экран «Нормативы»

Это должен быть простой справочник, а не библиотека документов.

Таблица:

```text
Группа | Для кого | Показатель | Норматив | Документ | Действует | Статус
```

Пример:

```text
Заместители директора | Школы | Классы | 1 на 12 классов | приказ № 123 | до 31.08.2027 | активен
Делопроизводство | Школы | Учащиеся | 1 на 300 учащихся | приказ № 123 | до 31.08.2027 | активен
Уборка помещений | Все | Площадь | 1 на 1000 м² | региональный закон № 45 | бессрочно | активен
```

Фильтры:

```text
Категория: АУП / Вспомогательный
Тип учреждения
Группа персонала
Документ
Только действующие
```

Редактировать могут только аналитик/администратор/уполномоченный специалист.

Директор может только смотреть применимые к своему учреждению.

## 7.5. Как не перегрузить интерфейс

Правила:

1. **Один главный экран — анализ.**  
   Не делать отдельную «штатку» ради штатки.

2. **Штатка и занятость — детали, а не первый уровень.**  
   Пользователь сначала видит проблему, потом ныряет в данные.

3. **Не показывать все должности сразу.**  
   Сначала категории и группы.

4. **Не делать древовидный справочник документов.**  
   Документ — это основание, а не основной объект интерфейса.

5. **Не смешивать заявки и аналитику.**  
   Заявка может быть связана с анализом, но анализ не должен жить внутри заявки.

6. **Использовать понятные статусы.**  
   Не «violating», не «non-compliant», а:
   ```text
   Дефицит
   Сверх норматива
   Норма
   Нет данных
   ```

7. **Скрыть нерелевантное по ролям.**  
   Сотрудник школы не должен видеть этот раздел вообще или видеть только свою заявку.  
   Директор — своё учреждение.  
   Специалист управления — свой муниципалитет.  
   Аналитик — регион.

8. **Мобильная версия — карточки.**  
   На телефете таблица превращается в список карточек:
   ```text
   Гимназия № 5
   АУП, сверх норматива +0,75
   Делопроизводство, заместители
   ```

# 9. Как связать с заявками

Сейчас у вас заявки уже определяют тему, исполнителя и срок. Новый модуль должен не ломать это, а обогащать кадровые заявки контекстом.

## 9.1. Какие темы уже есть

Из вашего описания подходят:

```text
Дополнительные ставки
Исправление данных
Вопрос по нормативам
Сокращение и реорганизация
Прочее
```

Их можно оставить.

## 9.2. Что добавить в заявку

В карточке заявки показать маленький блок только если заявка связана с нормативной численностью:

```text
Нормативный анализ

Учреждение: Гимназия № 5
Период: 2026/2027
Категория: АУП
Группа: Делопроизводство
Норматив: 1,00 ставки
Занято: 2,00 ставки
Отклонение: +1,00 ставки
Статус: сверх норматива
Основание: приказ № 123 от 01.09.2026
```

И кнопки:

```text
Открыть анализ
Изменить связь
```

Не надо впихивать весь анализ в заявку. Только суть и ссылку.

---

## 9.3. Создание заявки из анализа

Из панели анализа кнопка:

```text
Создать заявку
```

Открывает обычную форму заявки, но предзаполненную.

### Если дефицит

Тема:

```text
Дополнительные ставки
```

Текст можно сгенерировать шаблоном:

```text
По результатам нормативного анализа выявлен дефицит 0,75 ставки по группе «Бухгалтерия» в Гимназии № 5 на 2026/2027 учебный год.
Норматив: 1,25 ставки.
Занято: 0,50 ставки.
Основание: приказ управления образования № 123 от 01.09.2026.
Прошу рассмотреть вопрос о дополнительной ставке или уточнении штатного расписания.
```

### Если излишек по занятости

Тема:

```text
Сокращение и реорганизация
```

или, если не хотите сразу пугать, можно использовать тему:

```text
Вопрос по нормативам
```

Но по смыслу для управленческого решения лучше:

```text
Сокращение и реорганизация
```

Шаблон:

```text
По результатам нормативного анализа выявлен излишек 1,00 ставки по группе «Делопроизводство» в Гимназии № 5 на 2026/2027 учебный год.
Норматив: 1,00 ставки.
Занято: 2,00 ставки.
Основание: приказ управления образования № 123 от 01.09.2026.
Прошу проверить корректность штатного расписания и фактической занятости.
```

Важно: система не пишет «уволить сотрудника». Она пишет «проверить излишек ставки».

### Если нет данных

Тема:

```text
Исправление данных
```

Шаблон:

```text
Для нормативного анализа АУП в Школе № 44 отсутствуют данные: не указана общая площадь помещений.
Период: 2026/2027.
Прошу внести корректные данные для расчёта нормативной численности.
```

## 9.4. Маршрутизация

Можно расширить текущую логику `services/routing.py`.

Не обязательно делать новый большой движок. Достаточно правил.

### Дефицит

```text
Тема: Дополнительные ставки
Адресат: директор / специалист управления / аналитик
```

Можно оставить как сейчас, но уточнить:

```text
Если дефицит по АУП — управление образования.
Если дефицит по вспомогательному — хозяйственная служба/директор, при необходимости эскалация в управление.
```

### Излишек

```text
Тема: Сокращение и реорганизация
Адресат: региональный аналитик или специалист управления
```

Но если излишек маленький и локальный, лучше сначала директору:

```text
Если отклонение low/medium — директор + специалист управления.
Если high или системный по муниципалитету — аналитик.
```

### Нет данных

```text
Тема: Исправление данных
Адресат: директор или специалист управления, в зависимости от типа данных.
```

### Вопрос по нормативу

```text
Тема: Вопрос по нормативам
Адресат: региональный аналитик
```

# 10. Роли и доступ

Чтобы не было каши, права должны быть простыми.

| Роль | Что видит | Что может |
|---|---|---|
| Администратор | всё | настраивать справочники, сбрасывать данные, аудит |
| Региональный аналитик | весь регион | смотреть анализ, редактировать нормативы, создавать/вести заявки |
| Специалист управления | свой муниципалитет | смотреть анализ, создавать заявки, уточнять данные, частично редактировать локальные нормативы |
| Директор | своё учреждение | смотреть свой анализ, вносить штатку/занятость/метрики, создавать заявки |
| Наблюдатель | обезличенная сводка | только чтение, без деталей, если нужно |
| Сотрудник ОУ | не видит раздел | может только создавать обычные заявки |
| Хозяйственная служба | не видит кадровый анализ | только свои операционные заявки |

Очень важно:

```text
Сотрудник и хозяйственная служба не должны видеть раздел «Нормативная численность».
```

Иначе будет перегруз и лишние вопросы.

# 11. Что НЕ надо делать в первой версии

Чтобы интерфейс не стал громоздким, я бы явно исключил:

1. **Хранение сотрудников.**  
   Никаких ФИО, дат рождения, паспортов, СНИЛС, договоров.

2. **Зарплаты и оклады.**  
   Даже агрегированные фонды оплаты труда пока не нужны.

3. **Полноценный ЭДО.**  
   Не надо делать согласование приказов, маршруты подписания, ЭЦП.

4. **Хранение PDF/сканов.**  
   Сначала только реквизиты документа.

5. **Сложные формулы.**  
   Начать с простых коэффициентов: «1 ставка на X учащихся/классов/м²».

6. **Анализ учителей.**  
   Только АУП и вспомогательный.

7. **Автоматическое сокращение.**  
   Система только показывает отклонение. Решение принимает человек.

8. **Многоуровневое дерево документов.**  
   Это сразу превратит раздел в архив.

9. **Отдельную страницу «штатка» со сотнями строк.**  
   Штатка должна быть придатком анализа.

10. **Сразу массовые дашборды и графики.**  
   Сначала таблица проблем. Графики — потом.

# 15. Пример расчёта

## Исходные данные

Школа № 5:

```text
Учащихся: 840
Классов: 34
Площадь: 12000 м²
```

АУП:

```text
Заместители директора: утверждено 3,5, занято 3,5
Делопроизводство: утверждено 2,0, занято 2,0
Бухгалтерия: утверждено 1,0, занято 0,5
```

Нормативы условно:

```text
Заместители: 1 ставка на 12 классов
Делопроизводство: 1 ставка на 300 учащихся
Бухгалтерия: минимум 1,25 ставки при числе учащихся более 800
```

## Расчёт

### Заместители

```text
34 / 12 = 2,833
округление до 0,25 в большую сторону = 3,0
факт = 3,5
отклонение = +0,5
```

Статус:

```text
сверх норматива
```

### Делопроизводство

```text
840 / 300 = 2,8
округление до 0,25 в большую сторону = 3,0
факт = 2,0
отклонение = -1,0
```

Статус:

```text
дефицит
```

### Бухгалтерия

```text
минимум = 1,25
факт = 0,5
отклонение = -0,75
```

Статус:

```text
дефицит
```

## Итог по АУП

Можно показать агрегированно:

```text
Норматив: 7,25
Занято: 6,00
Отклонение: -1,25
Статус: дефицит
```

Но в деталях видно, что проблема не общая, а по группам:

```text
Заместители: +0,5
Делопроизводство: -1,0
Бухгалтерия: -0,75
```

Это гораздо полезнее, чем просто «школа не в норме».

# 16. Как показывать «излишки» корректно

Важно формулировать аккуратно.

Не надо:

```text
Лишний сотрудник
Сократить Иванова
Нарушение штатной дисциплины
```

Надо:

```text
Сверх норматива
Расчётный излишек
Отклонение от нормативной численности
Требует проверки
```

Пример:

```text
Группа: Делопроизводство
Норматив: 1,00 ставки
Занято: 2,00 ставки
Отклонение: +1,00 ставки
Статус: сверх норматива
Рекомендация: проверить актуальность штатного расписания и фактической занятости
```

Система не принимает кадровое решение. Она только подсвечивает расхождение.

# 17. Что делать с корпусами

У вас уже есть корпуса. Но не надо сразу усложнять.

Правило:

```text
По умолчанию анализ по учреждению целиком.
Корпуса показывать только если у учреждения больше одного корпуса и данные по корпусам заполнены.
```

В деталях можно добавить переключатель:

```text
Всё учреждение | Корпус A | Корпус B
```

Но на главном экране лучше не тащить корпуса, иначе таблица станет огромной.

# 18. Как быть с учебным годом и датами

Нормативы и штатка привязаны к периоду.

Лучше использовать:

```text
academic_year = 2026/2027
period_start = 2026-09-01
period_end = 2027-08-31
```

Анализ считать на конкретную дату, например:

```text
2026-10-20
```

Применяются те нормативы, которые действуют на эту дату.

Если заявка создана раньше, она должна ссылаться на результат анализа на дату создания или на дату, которую выбрал пользователь.

Поэтому в `staffing_analysis_results` хорошо хранить snapshot:

```text
какие коэффициенты применялись
какие метрики были
какая штатка была
```

Иначе потом норматив изменится, и старая заявка покажет другую картину.

# 19. Нужна ли локальная модель здесь

Не обязательно.

Для MVP достаточно правил и классификатора групп.

Модель можно использовать потом, чтобы из текста заявки предлагать:

```text
группу персонала
тип проблемы
период
учреждение, если не очевидно
```

Например, текст:

```text
У нас две секретарши, а по норме должна быть одна, причём одна на полставки
```

Модель может предложить:

```text
Категория: АУП
Группа: Делопроизводство
Проблема: излишек
```

Но это не критично для первой версии.

Главное — чтобы без модели всё работало по ключевым словам и ручному выбору.

# 20. pgvector: нужен ли сейчас

Пока нет.

У вас уже есть образ с pgvector, но для этого модуля на MVP он не нужен.

Достаточно:

```text
обычный поиск по названиям групп
поиск по документам
фильтры по метрикам
SQL-расчёты
```

pgvector пригодится позже, если захотите:

```text
семантический поиск по текстам нормативных документов
```

Но тогда надо хранить тексты документов, чанки, эмбеддинги, версию, права. Это отдельная большая история.

Сейчас лучше не открывать этот фронт.

# 22. Как сделать, чтобы директор не тонул в данных

Для директора нужен максимально простой экран.

Не таблица на 100 строк. А:

```text
Что не так в моём учреждении
```

Пример:

```text
Гимназия № 5 / 2026/2027
```

# 23. Как сделать, чтобы аналитик видел картину региона

Для аналитика главный вопрос не «какая должность», а «где системные проблемы».

Ему нужны:

```text
Топ учреждений по отклонению
Топ групп персонала по дефициту
Топ групп по излишку
Учреждения без данных
Муниципалитеты с наибольшим числом проблем
```

Но это можно сделать второй итерацией.

В MVP достаточно таблицы, отсортированной по:

```text
abs(deviation_fte) DESC
```

и фильтра:

```text
Только проблемы
```

Потом можно добавить сводку:

```text
По АУП:
дефицит в 12 учреждениях
излишек в 7 учреждениях

По вспомогательному:
дефицит в 18 учреждениях
излишек в 4 учреждениях
```

# 26. Как связаны заявка и анализ

Лучше сделать отдельную связь:

```text
request_staffing_links
```

Поля:

| Поле | Значение |
|---|---|
| `request_id` | Заявка |
| `analysis_result_id` | Результат анализа |
| `link_type` | `deficit`, `surplus`, `no_data`, `question`, `correction` |
| `created_by` | система или пользователь |
| `created_at` | когда |

Один заявка может быть связана с одним или несколькими результатами анализа.

Например:

```text
Заявка: проверить АУП в гимназии
Связи:
— Делопроизводство, излишек +1,0
— Заместители, излишек +0,5
— Бухгалтерия, дефицит -0,75
```

Но в UI показывать сначала агрегированно, детали по клику.

# 28. Acceptance criteria для MVP

## Данные

- Можно завести группу персонала для АУП или вспомогательного персонала.
- Можно внести утверждённые ставки по группе для учреждения и периода.
- Можно внести занятые ставки по группе без ФИО сотрудников.
- Можно внести метрики учреждения: учащиеся, классы, группы, площадь.
- Можно создать нормативный документ с номером, датой и сроком действия.
- Можно привязать нормативный коэффициент к группе, типу учреждения, метрике и документу.

## Анализ

- Система считает норматив по коэффициенту.
- Система округляет результат по настроенному шагу.
- Система применяет минимум и максимум.
- Система сравнивает норматив с утверждённой штаткой или занятостью.
- Система показывает статус: дефицит, сверх норматива, норма, нет данных.
- Система не показывает излишек или дефицит, если нет данных.
- Система сортирует проблемы по размеру отклонения.
- Система показывает причину отсутствия данных.

## Интерфейс

- Есть раздел «Нормативная численность».
- Есть вкладка «Анализ».
- Есть вкладка «Нормативы».
- На главном экране не более 6 колонок.
- Детали открываются по клику, а не показываются сразу.
- Директор видит только своё учреждение.
- Специалист видит только свой муниципалитет.
- Аналитик видит регион.
- Сотрудник и хозяйственная служба не видят раздел.

## Заявки

- Из анализа можно создать заявку.
- Заявка предзаполняется учреждением, периодом, категорией, группой и отклонением.
- В карточке заявки виден компактный блок нормативного анализа.
- Связь заявки и анализа попадает в аудит.

## Безопасность

- Персональные данные не хранятся.
- Доступ ограничен ролями и территорией.
- Изменения штатки, метрик и нормативов логируются.

# 30. Итоговая рекомендация

Делайте раздел не как «штатка + документы», а как:

> **Нормативный анализ численности АУП и вспомогательного персонала**

Ключевая ценность:

```text
Учреждение + период + категория + группа персонала
→ норматив
→ факт
→ отклонение
→ заявка
```

Интерфейс должен отвечать на три вопроса:

1. **Где проблема?**
   ```text
   Таблица учреждений с статусами и отклонениями
   ```

2. **В чём именно проблема?**
   ```text
   Drawer: по группам персонала, норматив, факт, основание
   ```

3. **Что сделать?**
   ```text
   Создать заявку / исправить данные / пересчитать
   ```

И обязательно:

```text
Без ФИО.
Без окладов.
Без сотрудников.
Только ставки, группы, метрики, нормативы и отклонения.
```

Тогда раздел будет полезным, понятным и не перегруженным.
